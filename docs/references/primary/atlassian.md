# Atlassian Design System reference pack

## Source and licensing

- Foundations: https://atlassian.design/foundations
- Design tokens: https://atlassian.design/foundations/design-tokens
- Motion: https://atlassian.design/foundations/motion
- Atlaskit source and package-specific licenses: https://bitbucket.org/atlassian/atlassian-frontend-mirror/

Atlassian packages and visual assets may use different terms. This repository links to guidance and stores original local analysis only.

## Transferable strengths

- Semantic token names describe intent instead of appearance.
- Content, accessibility, navigation, and visual foundations are one system.
- Motion preserves spatial origin and clarifies what changed.
- A stable core language can support a controlled, more expressive product dialect.

## Local adoption

- Token consumers choose by meaning, never by a coincidentally matching value.
- Content restraint is a first-class design-system concern.
- Drawers, overlays, and panels should originate from their owning control or region.
- Tool-specific accents behave as registered dialects over shared foundations.

## Rejected defaults

- Product dialects cannot multiply without governance.
- Component support for badges or descriptions does not justify repeating status or explanation.
- Atlassian branding is not reproduced.
