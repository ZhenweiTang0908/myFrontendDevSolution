# Promotion criteria

Promote when the change:

- solves a recurring product or interaction problem;
- has worked in a real page or workflow;
- can be expressed without private business data or one API contract;
- fits an existing profile and Page Pattern, or demonstrates a genuinely missing pattern;
- remains accessible and responsive;
- has a clear canonical state and testable behavior;
- reduces future AI guesswork more than it increases system complexity.

Keep local when the change:

- exists for one customer's branding or one data shape;
- works only because of a product-specific workflow;
- duplicates an existing component or pattern;
- adds a variant with no stable semantic meaning;
- has not yet been used enough to distinguish preference from requirement.

Choose the lowest authoritative layer:

- token for a reusable visual role;
- component for reusable anatomy and interaction;
- Page Pattern for information architecture or workflow;
- Golden Example for composition guidance;
- content rule for wording and repetition;
- verification for a recurring preventable failure.
